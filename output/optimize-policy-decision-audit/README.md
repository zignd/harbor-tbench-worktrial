# Optimize Policy Decision Auditing

The security platform team is auditing an internal SQL-backed authorization service after audit exports began timing out and occasionally disagreeing with the policy simulator. The repository contains the service, schema migrations, fixtures, query-history commits, and a command-line export path; the current implementation performs expensive per-request policy resolution over large tenant datasets.

## What it tests
- The agent reads only the current SQL and misses semantics encoded in migrations, callers, or Git history.
- The agent optimizes the obvious correlated subquery but does not reconstruct the complete precedence order.
- The agent assumes policy effects are globally deny-overrides-allow instead of discovering specificity-based selection.
- The agent uses a window partition that loses duplicate requests or duplicate policy bindings.
- The agent mishandles NULL interval ends or treats endpoint timestamps as inclusive.
- The agent uses an unstable tie-breaker and passes ordinary fixtures but fails generated equal-timestamp cases.
- The agent validates only the checked-in sample and never creates adversarial data.
- The agent produces correct results but misses the performance budget on dense candidate sets.
- The agent changes output ordering or CLI behavior while focusing on the SQL plan.
