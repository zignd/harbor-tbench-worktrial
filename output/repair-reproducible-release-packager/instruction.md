Repair `/opt/releaseforge` so `bin/releaseforge INPUT --out OUTPUT` reliably packages the release described by INPUT. INPUT is a directory containing `release.yaml`, `ci/build-events.jsonl`, `catalog/artifacts.jsonl`, and the payload files named by the catalog. The release file contains `name`, `platform`, `variant`, and root logical artifact identities in `roots`; it may be written as canonical JSON or as simple `key: value` YAML with `- item` list lines and is valid input in either form.

Select exactly one build attempt for each logical job: group records by logical job identity, choose the greatest attempt number, and count the job as selected only when that terminal attempt has status `success`; jobs with unsuccessful terminal attempts are excluded. Resolve the complete transitive dependency closure of the release roots for the requested platform and variant. Prefer an artifact matching both selectors, then matching one selector with `*` as the other, then the fully generic artifact. Apply this at every dependency level. Keep distinct logical identities distinct even when their payload bytes or digest are equal.

Read every packaged artifact from its catalogued path and verify its SHA-256 digest and declared size. Missing or altered payloads must cause a nonzero exit and must not publish an archive or metrics sidecar. On success, OUTPUT is a gzip-compressed archive containing canonical UTF-8 `manifest.json`, canonical UTF-8 `metrics.json`, and one payload member at `payload/<sha256>` for each distinct digest. The manifest contains an `artifacts` list with one entry per logical identity; each entry has `identity`, `digest`, `size`, `platform`, `variant`, and sorted dependency identities in `dependencies`.

Write the same metrics object as canonical JSON to `OUTPUT.metrics.json`. It has integer fields `selected_jobs`, `excluded_jobs`, `dependency_edges`, `artifact_count`, `payload_bytes`, and `cache_hits`, describing the final packaged closure; `cache_hits` is the number of logical artifacts sharing a digest with another packaged identity. JSON object keys and arrays must be stable. Archive bytes and both JSON representations must be byte-for-byte identical across reordered input records, changed file mtimes, locale settings, and different output directories. The supplied large fixture (under `/opt/releaseforge/docs/`) must also be packaged correctly.
