The audit contract is expressed as a lexicographic choice among applicable revisions. Tenant and action are equality constraints. Resource scope uses a prefix match. A revision applies when its start is no later than the event and its nullable end is strictly greater than the event. The selected row has the longest prefix, then greatest policy priority, newest revision timestamp, greatest revision sequence, and stable identifiers. The selected effect is returned unchanged; effects are not merged across scopes. The request relation is left-preserved so an empty candidate set still has an audit record.

The request sequence is assigned by ingestion and is the sole output ordering key. Request identifiers are labels rather than keys. A database may contain multiple bindings for one revision, and the identity of a binding participates only in making otherwise identical candidates deterministic.
