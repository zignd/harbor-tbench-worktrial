Settlement format reference

The manifest is UTF-8 JSON with secret, context, and nonnegative rotation integer fields. The batch key is obtained only from settle-crypto: SHA-256(secret bytes, one zero byte, context bytes). The helper accepts either two command-line strings or two newline-delimited strings on stdin and prints lowercase hexadecimal key bytes.

The spool is a sequence of frames. Each frame is uint32 little-endian payload length, payload, and 32-byte HMAC-SHA256(payload) using the derived batch key. A payload is: 16-byte reference, one ASCII kind byte, signed int64 little-endian amount, three ASCII currency bytes, then three uint16 little-endian length-prefixed byte fields (transaction id, description, metadata), followed by a uint32 little-endian rotation. Transaction kind T requires no trailing bytes after rotation. Adjustment kind A requires the three fields and rotation to be zero and then has a 16-byte target reference. Lengths are bounded by 65535; payloads are bounded by 1 MiB. All bytes, including zero bytes, are significant.

A transaction is accepted only after HMAC, structural validation, UTF-8 validation of id and description, supported currency validation, and rotation validation. An adjustment is accepted structurally and is applied once to its target reference; an unknown target is a rejection and never changes totals. Duplicate transaction references and duplicate adjustment identities are rejected. Frame offsets are byte offsets of their four-byte length prefixes. Rejection objects are {offset,reason}; reasons are authentication-failed, truncated-length, truncated-frame, invalid-length, unsupported-version, malformed, wrong-rotation, duplicate-reference, duplicate-adjustment, or unknown-reference.

Bank CSV has reference,amount,currency columns. A report is compact UTF-8 JSON with keys accepted, rejected, rejections, settlement_total, exception_total, currencies, audit_root, and status. accepted counts valid transactions only; rejected counts all rejected frames or unresolved adjustments. currencies is keyed in lexical currency order, each value has count and total after adjustments. settlement_total is the sum of adjusted transaction amounts and exception_total is the sum of signed adjustments. status is reconciled only if there are no rejections and every accepted transaction has an exactly matching bank amount and currency; otherwise exception.

The audit root is SHA-256 over the concatenation, in ascending raw 16-byte reference order, of uint32 little-endian payload length followed by each accepted transaction payload exactly as authenticated. JSON uses integer monetary values, UTF-8 strings are decoded only for reporting, and object insertion order is stable as listed above.
