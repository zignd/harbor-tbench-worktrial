Create an executable `/app/bin/incident-query.sh` that accepts a SQLite database path as its first argument and an output TSV path as its second argument. It must write one line per authoritative audit event, with exactly `event_id<TAB>account<TAB>epoch<TAB>sequence`, no header, ordered deterministically by epoch and then sequence.

The supplied database has these tables and columns: `epochs(epoch,prime,threshold,commitment)`, `shares(epoch,x,y)`, `events(event_id,account,epoch,sequence,predecessor,payload,mac)`, `anchors(epoch,event_id)`, `checkpoints(epoch,sequence,event_id,signature)`, `accounts(account,description)`, and `incident_metadata(name,value)`. Each epoch's scalar is the value at zero of a degree-threshold-minus-one polynomial over the documented prime p=2^127-1. Shares are Shamir points `(x,y)` and the commitment is SHA-256 of the scalar's decimal representation. Recover the scalar from any threshold subset whose interpolation matches that commitment; share rows may be in arbitrary order and some may be corrupt.

Event authentication is HMAC-SHA256 over big-endian uint64 epoch, big-endian uint64 sequence, the 32 raw bytes of the predecessor digest, big-endian uint32 account UTF-8 length, account UTF-8 bytes, big-endian uint32 payload UTF-8 length, and payload UTF-8 bytes. A checkpoint signature is HMAC-SHA256 over the ASCII bytes `checkpoint|epoch|sequence|event_id` using that epoch key. A predecessor digest is the lowercase hexadecimal SHA-256 digest of the predecessor event_id.

Emit only events on an anchor-rooted, predecessor-linked chain for that epoch whose event MACs are valid, whose sequence starts at the anchor and advances contiguously by one, and whose final event is exactly identified by a valid signed checkpoint. Exclude forged, malformed, stale-key, orphaned, duplicate-sequence, and locally valid fork records that do not belong to such a checkpointed chain. Treat epochs independently, including key rotations, and handle arbitrary valid UTF-8 account and payload text. Never emit malformed lines. The command must be deterministic and classify at least 99.5% of events correctly on fresh verification databases.
