Create an executable file at `/opt/incident/bin/incident-query.sh` (and make the same command available as `bin/incident-query.sh` from `/opt/incident` if needed). It must accept a SQLite database path as its first argument and an output TSV path as its second argument.

The command must write one line for every authoritative audit event and no other event. Each line must contain exactly four tab-separated fields: event_id, account, epoch, and sequence, with no header. Epoch and sequence must be decimal integers. The output must be deterministic and sorted by epoch, then sequence.

Authoritative events are the events that belong to an authentic, contiguous audit chain beginning at that epoch's recorded anchor and ending at a valid signed terminal checkpoint. Validate the epoch key material, event authentication, predecessor links, canonical event encoding, and checkpoint signatures. Exclude forged, invalid, stale, orphaned, fork-only, duplicate, and non-checkpointed events. The command must handle every epoch independently and must work for fresh verification databases with reordered or corrupted shares, multiple rotations, forks, gaps, malformed digests, varied accounts and payloads, and thousands of events. It must never emit malformed lines and must classify at least 99.5% of events correctly.
