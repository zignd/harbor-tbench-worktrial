Repair `/app/output/environment/bin/replay INPUT_DIR OUTPUT_DIR` so it is trustworthy for a backfill. It must recursively process every regular file whose name ends in `.log`, continue after bad physical lines, and write deterministic `events.csv`, `sessions.csv`, `metrics.csv`, and `rejects.csv` in the requested output directory. Rerunning with an existing or partially written output directory must produce the same files without duplicate rows.

A valid physical line is one UTF-8 JSON object with exactly the keys `event_id`, `ts_ms`, `tenant`, `session`, `op`, `latency_us`, and `status`. `event_id` is a unique nonempty ASCII identifier of at most 80 characters; `ts_ms` is an integer from 0 through 4102444800000; `tenant` and `session` match `[A-Za-z0-9_-]+` and have lengths 1-32 and 1-64; `op` is `start`, `hit`, `finish`, or `error`; `latency_us` is an integer from 0 through 2147483647; and `status` is `ok` or `fail`. Duplicate JSON keys, extra keys, invalid UTF-8, control characters, wrong JSON types, and constraint violations are rejects rather than partially parsed events.

Keep one copy of each valid event ID, choosing the earliest record under `(ts_ms, relative_filename, physical_line_number, event_id)` when an ID repeats. Emit accepted events in that same order. A session is accepted only when its `(tenant, session)` group has exactly one `start` and one `finish`, the start is no later than every event and every event is no later than the finish, and all events pass validation; otherwise none of that session's events contribute to metrics. `sessions.csv` must contain tenant, session, start_ms, finish_ms, event_count, error_count, and duration_ms for each accepted session.

`metrics.csv` must contain one row for every tenant/op pair present in accepted sessions, with event_count, ok_count, fail_count, latency_sum_us, latency_max_us, and nearest-rank p95 latency (rank `ceil(0.95*n)` after sorting accepted event latencies). CSV fields must be correctly quoted and all files must have headers. `rejects.csv` must include relative filename, physical line number, and a stable reason. Output must not depend on filesystem enumeration order, and malicious strings must be treated as data rather than SQL or shell syntax.
