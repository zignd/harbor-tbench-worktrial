Deploy the beacon catalog service at `/opt/beacon/bin/beacond` and have it listen on TCP port `4711` without using network access or additional dependencies. It must read `.cap` captures from `/opt/beacon/data` and rebuild its catalog by invoking `/opt/beacon/bin/catalog-build`.

The service accepts newline-delimited JSON requests and returns one JSON response per line. Support `{"op":"lookup","device":"<16 uppercase hex characters>","at":<integer>}`, `{"op":"history","device":"<16 uppercase hex characters>","from":<integer>,"to":<integer>}`, `{"op":"stats"}`, and `{"op":"reload"}`. Lookup responses must contain `ok`, `device`, `value`, `quality`, and `source_seq`; history responses must contain `ok`, `device`, and an ordered `records` array whose records contain `at`, `value`, `quality`, and `source_seq`; stats responses must contain `ok`, `records`, `devices`, `rejected`, and `generation`; reload responses must contain `ok` and `generation`.

Use inclusive timestamp bounds. For a known device, lookup returns the observation at the requested timestamp, or the documented non-success error for an unavailable timestamp; missing devices and invalid ranges must also use the documented non-success error rather than fabricated data. History is ordered by timestamp and then deterministic source order, removes exact duplicate observations, and preserves source sequence values including 32-bit rollover. Malformed JSON, incomplete requests, and unknown operations must receive documented non-success JSON responses while keeping the connection usable. Reload must atomically replace the snapshot and statistics so every request observes one internally consistent generation. The service must handle the supplied captures and new capture directories produced by `/opt/beacon/tools/make_case.py`.
