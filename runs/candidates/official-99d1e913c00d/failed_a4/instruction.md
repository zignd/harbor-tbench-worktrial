Deploy the Beacon Catalog Service at `/opt/beacon/bin/beacond` and keep it listening on TCP port `4711` without network access or downloaded dependencies. It must rebuild its catalog from `.cap` files in `/opt/beacon/data` by invoking `/opt/beacon/bin/catalog-build`, and it must also work after `/opt/beacon/tools/make_case.py --seed SEED --out DIRECTORY` creates replacement capture directories.

Accept multiple newline-delimited JSON requests on each TCP connection. Support `lookup` with string `device` (exactly 16 hexadecimal characters) and integer `at`, `history` with `device` and integer inclusive `from` and `to`, `stats`, and `reload`. Follow every response schema, error name, field type, inclusive boundary, ordering, quality tie-break, unsigned source-sequence behavior, and missing-device rule in `/opt/beacon/PROTOCOL.md`. In particular preserve `device`, `value`, `quality`, and integer `source_sequence` on lookup responses and the complete ordered record fields on history responses; never fabricate records for missing devices or out-of-range timestamps.

Reload must publish the newly built snapshot and statistics as one atomic generation. Every individual lookup, history, stats, or reload response must use one internally consistent generation, including while clients issue requests concurrently. The service must remain usable on the supplied captures and large generated cases within the machine's 2 GB memory limit, and must return the documented errors for malformed JSON, incomplete requests, and unknown operations.
