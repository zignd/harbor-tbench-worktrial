Deploy `/opt/beacon/bin/beacond` as a reliable newline-delimited JSON TCP service listening on port `4711`, without network access or downloaded runtime dependencies. It must read all `.cap` files under `/opt/beacon/data` and rebuild its catalog by invoking `/opt/beacon/bin/catalog-build`.

Support lookup requests with `op`, a 16-hex-character `device`, and integer `at`; history requests with `op`, `device`, integer `from`, and integer `to`; and `stats` and `reload` requests. Responses must follow `/opt/beacon/PROTOCOL.md`, including exact success and error fields, device, value, quality, source sequence, inclusive history bounds, deterministic ordering, duplicate handling, and uint32 sequence rollover behavior. Missing devices and unavailable timestamps must return the documented non-success response.

Support malformed JSON, invalid requests, unknown operations, and multiple requests on one connection according to the protocol. Reload must atomically publish one immutable generation containing both catalog data and statistics, so every request observes internally consistent snapshot and sidecar data. The service must work with the supplied captures and fresh capture directories generated by `/opt/beacon/tools/make_case.py`, remain within the supplied 2 GB machine, and use bounded resources.
