MAFv2 binary stream protocol

A frame begins with the four bytes `MAF2` (hex 4d 41 46 32). The fixed header including the sync is 20 bytes; the fields after the sync occupy 16 bytes: uint16 little-endian rows m, uint16 little-endian columns n, uint32 little-endian sequence, uint32 little-endian payload length, and uint32 little-endian reserved (which must be zero). The payload is followed by a four-byte little-endian CRC32C (Castagnoli) of the payload only.

A payload has exactly `(m*n + m + n) * 8` bytes, consisting of m*n binary64 basis values in row-major order, then m binary64 eigenvalues, then n binary64 physical-vector values. Valid dimensions satisfy 1 <= m <= 12 and 1 <= n <= 12. The advertised payload length must equal the required size and must be bounded before any read or allocation. All values must be finite. Compute q[j] = sum_i basis[j,i] * x[i]. Compute energy as sum(q[j]^2 / eigenvalue[j]). An eigenvalue greater than zero is required unless q[j] is exactly zero, in which case a zero eigenvalue contributes zero. Negative eigenvalues are invalid. A frame is accepted only after complete payload, CRC, and all semantic checks succeed.

The canonical output is one compact JSON object per line with exactly these fields: `sequence` (unsigned integer), `coefficients` (array of m JSON numbers in row order), and `energy` (JSON number). No other standard-output text is part of the protocol. Arbitrary bytes, incomplete or invalid frames, and embedded sync patterns may occur between accepted frames; recovery searches for the next sync candidate byte by byte.
