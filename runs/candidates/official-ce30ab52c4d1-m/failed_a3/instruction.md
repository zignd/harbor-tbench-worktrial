Repair the funnel service in `/app` without changing its HTTP contract. `./run.sh` must start a service listening on port 8080, and `/health` must return HTTP 200 with JSON `{"status":"ok"}`.

`POST /v1/reset` accepts an empty JSON object, removes all event and derived state, and returns HTTP 200 JSON with boolean field `ok`. `POST /v1/append` accepts JSON containing an `events` array; each event has `event_id`, `user_id`, `occurred_at` (UTC ISO-8601), `ingest_seq`, and `kind`, plus applicable `campaign`, `order_id`, and `amount_cents` fields. It returns HTTP 200 JSON with integer field `accepted`. Invalid JSON or malformed requests must receive a 4xx response.

`POST /v1/report` accepts JSON with optional `since` and `until` UTC ISO-8601 timestamps defining the half-open interval `[since, until)`, and an optional campaign filter supplied as either `campaigns` (an array) or `campaign` (a string). It returns HTTP 200 JSON containing a `rows` array. Each row has `campaign_name` (string), `session_count`, `purchase_count`, and `net_revenue_cents` (integer). Include observed attribution campaigns and explicitly requested campaigns even when their values are all zero. Apply campaign filtering after attribution. Sort rows by descending net revenue and then ascending campaign name.

For duplicate event IDs, retain exactly the event with the greatest ingest sequence regardless of append order; replaying an already retained event is idempotent. Order each user's retained events by UTC occurred time, then ingest sequence, then event ID. Start a new session only when the gap from the preceding retained event is greater than 1800 seconds; a gap of exactly 1800 seconds remains in the same session. Attribute a purchase to the most recent touch in its session at or before the purchase, or `(direct)` when none exists. A refund reverses the purchase identified by its order ID, uses that purchase's original campaign attribution even across sessions, and repeated refunds cannot subtract an order more than once. Each order contributes at most once to purchase and revenue totals.

For a report, include sessions with at least one retained event in `[since, until)`, and include only purchases and refunds whose own timestamps are in that interval. Reports must be deterministic after out-of-order appends, duplicate corrections, late events, and session-boundary changes. Keep the endpoint paths, JSON field names, port, and launcher unchanged.
