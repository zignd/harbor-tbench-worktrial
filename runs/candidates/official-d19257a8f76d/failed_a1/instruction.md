Repair `/opt/burstreplay/bin/replayd` and `/opt/burstreplay/bin/replay.sh` so the documented local replay service is reliable.

`/opt/burstreplay/bin/replayd` must read one JSON object per stdin line and emit exactly one JSON object per input line, without using a network port. Requests use string field `op` and string field `run`: `reset` discards only that run and returns `{"ok":true,"op":"reset","run":...}`; `ingest` additionally has string field `trace` and returns `{"ok":true,"op":"ingest","run":...,"ingested":N}`; `report` returns the complete report for that run. Runs are independent, state persists across requests in one process, and a missing run reports zero data. Invalid JSON, unknown operations, missing fields, and malformed records must return one deterministic error object with `ok:false`, an `error` string, and a numeric `line` for record errors, then continue processing later requests.

Each trace is UTF-8 text containing logical records in escaped pipe format. A record has six fields: `timestamp|name|value|weight|payload|checksum`. Separators inside a field are written `\\|`, backslashes are written `\\\\`, and a field containing a newline is enclosed in double quotes; doubled quotes inside quoted fields represent one quote. Physical newlines inside quoted fields are continuations, not record boundaries. Empty fields and Unicode are valid. The checksum is eight lowercase hexadecimal CRC32, computed over the UTF-8 bytes of the first five decoded fields joined by literal `|`. Timestamp is a nonnegative integer milliseconds, value and weight are nonnegative integers, and malformed records are rejected deterministically.

For a valid ingest, decode every record, retain its arrival index, sort records by `(timestamp, arrival index)`, and split them into sessions: a new session starts when the gap from the preceding event in sorted event time is greater than 60000 milliseconds. For each session, compute `units` as the sum of `value*weight`; `peak` is the largest single `value*weight` in the session; and the report aggregates all sessions. The report object must contain `ok`, `op:"report"`, `run`, integer `events`, integer `sessions`, integer `units`, integer `peak`, a `histogram` object whose keys are decimal session event counts and values are integer counts, and lowercase eight-digit hexadecimal `checksum`. The checksum is CRC32 over UTF-8 JSON with sorted keys and compact separators of the report fields excluding `ok` and `checksum`. Reports must be deterministic and use integer arithmetic.

`/opt/burstreplay/bin/replay.sh` must accept `--trace FILE --run RUN`, invoke replayd locally with no network access, print the report JSON, remove its temporary staging data on success or failure, and propagate a nonzero status when the trace is missing or invalid. It must work for repeated invocations and generated temporary paths. Keep all behavior deterministic and do not depend on wall-clock time or randomness.
