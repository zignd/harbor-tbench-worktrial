Repair `/opt/burstreplay/bin/replayd` and `/opt/burstreplay/bin/replay.sh` so the documented local replay service is reliable.

`/opt/burstreplay/bin/replayd` must read one JSON object per stdin line and emit exactly one JSON object per input line, without using a network port. Every request has string fields `op` and `run`; `reset` discards only that run and returns `{"ok":true,"op":"reset","run":...}`, `ingest` additionally requires string field `trace` and returns `{"ok":true,"op":"ingest","run":...,"ingested":N}`, and `report` returns the complete report for that run. State persists across requests in one process, runs are independent, reset affects only its selected run, and a missing run reports zero data.

Invalid JSON, blank input, unknown operations, non-object requests, missing fields, wrong field types, and extra-invalid request shapes must each produce one deterministic JSON error object with `ok:false` and `error:"invalid_request"`; the process must continue with later requests. An ingest containing any malformed record must produce one error object with `ok:false`, `error:"invalid_record"`, and numeric one-based physical `line`, must not partially apply that ingest, and must continue serving later requests.

Each trace is UTF-8 text containing logical records in escaped pipe format. A record has six fields: `timestamp|name|value|weight|payload|checksum`. Separators inside a field are written `\\|`, literal backslashes are written `\\\\`, and a field containing a physical newline is enclosed in double quotes; doubled quotes inside quoted fields represent one quote. Physical newlines inside quoted fields are continuations, not record boundaries. Empty fields and Unicode are valid. Quotes are valid only for a field's complete quoted representation. The checksum is eight lowercase hexadecimal characters and is CRC32 over the UTF-8 bytes of the first five decoded fields joined by literal `|`. Timestamp, value, and weight are nonnegative decimal integers; all other malformed records, including wrong field count, bad escapes, unterminated quotes, invalid numeric fields, uppercase/non-hex/wrong-length checksums, and checksum mismatches, are rejected.

For a valid ingest, decode every record, retain its arrival index, sort records by `(timestamp, arrival index)`, and split them into sessions: a new session starts when the gap from the preceding event in sorted event time is greater than 60000 milliseconds. For each session, compute `units` as the sum of `value*weight`; `peak` is the largest single `value*weight` in the session; and the report aggregates all sessions. The report object must contain `ok:true`, `op:"report"`, `run`, integer `events`, integer `sessions`, integer `units`, integer `peak`, a `histogram` object whose keys are decimal session event counts and values are integer counts, and lowercase eight-digit hexadecimal `checksum`. The checksum is CRC32 over UTF-8 compact JSON with sorted keys for the report fields excluding `ok` and `checksum`. Reports must be deterministic and use integer arithmetic.

`/opt/burstreplay/bin/replay.sh` must accept exactly `--trace FILE --run RUN`, invoke replayd locally with no network access, print exactly the report JSON, remove temporary staging data on success or failure, and propagate a nonzero status when arguments are invalid, the trace is missing/unreadable, or the trace is invalid. It must work for repeated invocations and generated temporary paths. Keep all behavior deterministic and do not depend on wall-clock time or randomness.
