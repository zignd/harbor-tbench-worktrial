# Assay cohort report contract

The database has tables `runs(run_id,priority,calibration_unit,slope,intercept)`, `unit_factors(unit,factor)`, `measurements(measurement_id,run_id,cohort_id,analyte,well,sequence,timestamp,quality,phase,value,unit,crc32)`, `export_fragments(fragment_id,run_id,fragment_no,payload)`, `controls(control_id,cohort_id,analyte,kind,run_id,well,sequence,timestamp,quality,value,unit,crc32)`, and `cohorts(cohort_id)`. Fragment payloads are UTF-8 JSON Lines; a record is an object with the measurement fields and `crc32`, whose decimal or hexadecimal value is CRC32 of compact sorted-key JSON of the object without `crc32`. Lines are independently recoverable: malformed lines are skipped and bytes may split records between fragments.

A usable record has nonempty identifiers, phase `pre` or `post`, finite numeric value, nonnegative quality, and a valid CRC. Convert `value` to the run calibration unit by multiplying by `unit_factors[unit] / unit_factors[calibration_unit]`, then compute `slope*x+intercept`. For each `(cohort,analyte,well,sequence)`, retain the greatest `(run.priority, sequence, timestamp, quality, measurement_id)` tuple, with textual stable IDs as the final tie breaker. Keep quality at least 0.5. Controls use the same recovery, conversion, quality, and duplicate rules.

For each cohort/analyte/phase, normalize a retained sample as `(calibrated-negative)/(positive-negative)`, where controls are the medians of retained control values for that cohort/analyte and kind. A missing control makes normalized values non-computable. Apply Tukey filtering independently to each phase using inclusive quartiles from the sorted values (`q(p)` is linear interpolation at `p*(n-1)`) and retain values in the inclusive fence `[q1-1.5*(q3-q1),q3+1.5*(q3-q1)]`. Aggregate retained replicates by median (average of the two middle values). The effect is the median of every `post_value-pre_value` pair; with no pairs it is null.

Output is an object `{"records":[...] ,"schema_version":1}`. Every record has exactly `cohort_id`, `analyte`, `n_pre`, `n_post`, `positive_control`, `negative_control`, `pre_median`, `post_median`, and `effect`; counts are integers and non-computable values are JSON null. Records include every cohort/analyte combination represented by a cohort and either measurement or control, sorted lexicographically by cohort_id then analyte. Serialize compact UTF-8 JSON with sorted object keys and one final newline. The database is read-only.
