Our NetFlow settlement aggregator at /app is producing wrong per-counterparty byte totals for some traffic classes the numbers do not match what the routers report via SNMP. No reproduction script was left.

The service reads NetFlow v9 binary files from a directory, looks up each flow source IP in /app/data/asn_map.csv (a CIDR-prefix-to-ASN mapping table), classifies each flow by its DSCP value using /app/data/traffic_class_map.csv, and writes per-counterparty per-traffic-class byte totals to settlement.csv in the current working directory.

The rules are: each data flowset record byte count must be attributed to the counterparty identified by the source-IP-to-ASN mapping table; each flow traffic class is determined by its DSCP value (ToS byte right-shifted 2 bits) looked up in traffic_class_map.csv, defaulting to default if the DSCP value is not listed; when a flow template is re-exported mid-file the aggregator must use the most-recently-seen field layout for all subsequent records in that file; multi-file runs must carry template state forward across files in the order the files are processed, sorted by filename.

Fix /app so that running `python /app/settle.py /app/data/` produces a settlement.csv with columns asn,traffic_class,total_bytes whose per-counterparty per-traffic-class byte totals match the reference computation for any valid set of NetFlow v9 binary input files.
