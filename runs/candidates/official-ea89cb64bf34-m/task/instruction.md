Repair the replay service in /opt/replay so that `/opt/replay/bin/replayd` runs as a line-oriented JSON service on stdin and stdout. It must emit no unsolicited stdout and must use only the request and response formats in `/opt/replay/PROTOCOL.md`.

Recover authoritative state from `/var/lib/replay/segments` and `/var/lib/replay/catalog.db`. A recover request must apply only valid, committed records, preserve transaction ordering, ignore truncated final frames, and stop scanning a segment at the first malformed frame. It must handle empty segments, records larger than normal buffers, records split at any byte boundary, duplicate writer-local sequence numbers, Unicode keys and values, empty values, separator-containing keys, deletes, and later recreation. Aborted and incomplete transactions must not affect live state or audit history.

Point reads, prefix listings, tenant statistics, the SQLite catalog, manifest/checksum responses, and audit responses must describe one consistent recovered state. Lists must be deterministic and sorted by key. Statistics must count a present empty value as a live object and must include tenants that have events but no live objects. Audit history must retain committed puts and tombstones in deterministic transaction order without duplicates. Repeating recovery over unchanged files must leave every response, catalog row, watermark, and manifest unchanged.

Put and delete requests must durably update live objects, event history, generation metadata, and manifest data together closely enough that a restart cannot expose a partial operation. After restarting the documented command, all reads, listings, statistics, audit results, and manifest values must remain unchanged. The service must support multiple tenants and return documented errors for invalid or missing requests.
