Known Issues — Metrics Pipeline
================================

Last updated: 2024-01-28
Maintainer: platform-infra@company.internal


ISSUE-001: NaN returned intermittently for low-traffic services
---------------------------------------------------------------
Status: Open
Severity: Medium
Affected: scheduler, mailer (and any service with sparse log data)

Some queries against low-traffic services return NaN for certain time buckets
instead of a numeric aggregate. This appears to happen more often with smaller
window sizes (e.g. 60s or 300s buckets) where individual windows have few data
points.

Root cause: Not fully investigated. The engine may have internal thresholds for
minimum data density. Workaround: use larger window sizes or fall back to direct
database computation for affected buckets.

ISSUE-002: Boundary alignment may differ from docs
---------------------------------------------------
Status: Open
Severity: Low-Medium
Affected: All services

The engine_wrapper.py docstrings describe window intervals as "inclusive on both
ends". In practice, queries on data where a log entry falls exactly on a bucket
boundary sometimes assign that entry to the adjacent bucket rather than the
expected one.

Root cause: Unclear. The compiled engine may use slightly different interval
semantics than what the wrapper documentation describes. This discrepancy was
noted by Marcus during the original integration work but not fully resolved
before he left.

Workaround: If exact boundary alignment matters, run experiments with known
data and compare results against expectations. The logbin_probe CLI tool can
help with this.

ISSUE-003: Ingestor skips files if ingest_log table is corrupted
----------------------------------------------------------------
Status: Resolved (v1.4.2)
Severity: Low

Fixed in v1.4.2 by adding error handling around ingest_log reads. No longer
reproducible with current codebase.

ISSUE-004: query_service.py not yet implemented
------------------------------------------------
Status: Open (blocking dashboard team)
Severity: Critical

The HTTP query service that dashboards depend on has not been implemented.
The engine wrapper and ingestor are functional; the service layer needs to
be built on top of them. See QUERY_PROTOCOL.md for the required API.

This is the current priority item.
