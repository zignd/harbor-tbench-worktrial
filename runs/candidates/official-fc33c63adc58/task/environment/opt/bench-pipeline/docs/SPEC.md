# Telemetry Trace Reproduction Pipeline Specification (v2)

## Overview
The pipeline reproduces benchmark metrics from chunked binary telemetry trace spools generated by the `traced` daemon.

## Frame Format (v2)
Trace spools and streams consist of framed binary chunks encoded in Big-Endian network byte order.

### Frame Header (16 bytes)
- Bytes 0..3:  Magic number `0x54524143` (ASCII "TRAC")
- Bytes 4..5:  Channel ID (`uint16`, 0 to 65535)
- Bytes 6..7:  Flags (`uint16`)
  - `0x0001`: SYNC frame
  - `0x0008`: CONTINUATION flag (payload split across chunks; more chunks follow for this channel)
- Bytes 8..11: Chunk Sequence number (`uint32`, monotonic per channel)
- Bytes 12..15: Payload length in bytes (`uint32`)

### Frame Alignment
Each frame is padded at the end with zero bytes to align to an 8-byte boundary. Specifically:
```
frame_total_size = ((16 + payload_length + 7) / 8) * 8
padding_bytes = frame_total_size - (16 + payload_length)
```
The padding bytes must be skipped before reading the next frame header.

### Chunk Reassembly
When a frame has the CONTINUATION flag (`0x0008`) set, its payload contains a partial fragment of event data. Payloads from frames of the same channel must be accumulated in sequence order until a frame without `0x0008` is received. The accumulated payload is then decoded as a sequence of events.

## Event Types inside Reassembled Payloads
Events are packed contiguously inside payloads. Each event begins with a 1-byte Event Type:

1. `0x01` (CHANNEL_ANCHOR, 17 bytes):
   - `anchor_timestamp_micros`: 8 bytes (`uint64`, microsecond epoch timestamp)
   - `reserved`: 8 bytes (`uint64`)
   Sets the base anchor timestamp for the channel.

2. `0x02` (SPAN_START, 13 bytes):
   - `span_id`: 8 bytes (`uint64`)
   - `delta_micros`: 4 bytes (`uint32`, microsecond tick counter relative to anchor)

3. `0x03` (SPAN_END, 13 bytes):
   - `span_id`: 8 bytes (`uint64`)
   - `delta_micros`: 4 bytes (`uint32`, microsecond tick counter relative to anchor)

4. `0xAA` (LIFECYCLE_PHASE, 6 bytes):
   - `phase_id`: 1 byte (`uint8`): 0 = `warmup`, 1 = `measurement`, 2 = `cooldown`
   - `delta_micros`: 4 bytes (`uint32`)

## Timestamp Normalization
Per-worker counter deltas (`delta_micros`) are 32-bit unsigned integers ticking at 1 MHz (microseconds). The 32-bit counter rolls over every $2^{32}$ microseconds (~71.58 minutes).
When processing events chronologically on a channel, detect wraparound:
if `delta < last_delta` and `(last_delta - delta) > 0x80000000`, the counter has wrapped around, incrementing the wrap counter by $2^{32}$.
The normalized timestamp for an event on channel $c$ is:
```
timestamp = channel_anchor_timestamp[c] + (wrap_count[c] * 0x100000000) + delta
```

## Cross-Channel Span Reconciliation
- A span is correlated by matching a `SPAN_START` event with a `SPAN_END` event having the identical 64-bit `span_id`.
- The start and end events may originate from different worker channels.
- Duration is calculated as:
```
latency_micros = end_timestamp - start_timestamp
```
- If `SPAN_START` or `SPAN_END` is unmatched (orphaned span), it is discarded from latency calculations.

## Lifecycle Phase Partitioning
A span is assigned to a phase based on its `SPAN_START` timestamp:
- Phase `warmup`: `warmup_timestamp <= start_timestamp < measurement_timestamp`
- Phase `measurement`: `measurement_timestamp <= start_timestamp < cooldown_timestamp`
- Phase `cooldown`: `start_timestamp >= cooldown_timestamp`
Spans starting before the first `warmup` marker or after trace conclusion without phase assignment are not counted in the 3 phases.

## Percentile Calculation Method
Latency percentiles ($P_{50}, P_{95}, P_{99}$) for each phase are calculated using Type 7 linear interpolation (standard nearest-rank linear interpolation):
Given $N$ sorted latencies $v_0 \le v_1 \le \dots \le v_{N-1}$:
For percentile $P \in [0, 100]$:
```
k = (P / 100.0) * (N - 1)
i = floor(k)
f = k - i
percentile_value = (i < N - 1) ? (v[i] + f * (v[i + 1] - v[i])) : v[N - 1]
```
If $N = 0$, latencies are 0.00.
Results must be rounded to 2 decimal places.

## Output JSON Schema
`--output <FILE>` must write valid JSON matching:
```json
{
  "total_spans": <int>,
  "dropped_frames": <int>,
  "phases": {
    "warmup": {
      "span_count": <int>,
      "p50": <float>,
      "p95": <float>,
      "p99": <float>
    },
    "measurement": {
      "span_count": <int>,
      "p50": <float>,
      "p95": <float>,
      "p99": <float>
    },
    "cooldown": {
      "span_count": <int>,
      "p50": <float>,
      "p95": <float>,
      "p99": <float>
    }
  }
}
```
`total_spans` is the sum of `span_count` across all three phases.
`dropped_frames` is the count of malformed or skipped frames.
