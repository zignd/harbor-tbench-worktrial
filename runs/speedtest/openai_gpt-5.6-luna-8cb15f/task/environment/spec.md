# Service specification
`GET /healthz` returns 200 and `{"status":"healthy"}`.
`POST /v1/query` accepts `{"endpoint":string,"time_range":[start,end],"metrics":[...]}` and returns an object containing each requested metric. The range is half-open and selects frontend request start times. `GET /v1/attribution/stats` returns `total_frontend`, `matched`, `unmatched`, `matched_slacks`, and `backend_records`.
Metrics are matched_count, unmatched_frontend_count, p50_backend_latency, p90_backend_latency, p99_backend_latency, and error_rate. Percentiles use nearest rank: sorted list element at ceil(p*n)-1; empty latency sets return null. Error rate is failed matched tasks divided by matched tasks.
Binary files have a 16-byte little-endian header `<4sBBHQ`: magic `BPK1`, version, flags, record count, and base timestamp. Each record is `<HBBiI` followed by an endpoint of the indicated length: worker, endpoint length, signed worker exit code, signed delta milliseconds, and duration milliseconds. The start of each record is the previous start plus delta, beginning at base_ms; end is start+duration.
Attribution requires exact endpoint, strict containment of backend interval in frontend interval, compatible status (failed means frontend 502 or 504), and no overlapping tasks on one worker. Among valid global assignments, minimize total slack; each frontend and task is used at most once.
