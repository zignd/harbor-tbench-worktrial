We're closing out the telemetry migration service in /opt/telemetry-service. The ingress used to strip downstream trace headers, so frontend access logs in /var/log/telemetry/frontend and backend execution logs in /var/log/telemetry/backend have no shared request IDs. Read README.md and docs/spec.md before changing anything.

The daemon telemetry-queryd needs to be live on 0.0.0.0:8085 and serve GET /healthz, POST /v1/query, and GET /v1/attribution/stats with the schemas and status codes in docs/spec.md. It has to decode every legacy .bpack using the packed layout in legacy/bpack.h, including the fixed epoch header, variable-length endpoint strings, signed record deltas, and execution durations. It also has to parse the six-column frontend TSV logs. The attribution layer must enforce endpoint equality, strict temporal containment, per-worker non-overlap, and failure-status consistency, then apply the minimum-slack allocation rule documented in the spec. The query metrics must use those attributed sessions and the documented nearest-rank percentiles and inclusive/exclusive query-window semantics.

Historical files are only a sample. The daemon must pick up newly appended .tsv and .bpack files on subsequent requests without losing earlier data. Keep the service stable under concurrent queries. After any changes, systemctl restart telemetry-queryd or the equivalent /opt/telemetry-service/run.sh restart must leave the daemon healthy.
